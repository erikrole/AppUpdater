# AppUpdater audit — October 23, 2026

Audited package baseline: `28a75e23e183c5ed036ace4cb915e876c1ce1d5a` (`main`). Scope includes release parsing,
download lifecycle, verification, preparation, swap/recovery, relaunch, quit fallback, release-note links/tooling,
and a read-only inventory of local integrations. An independent review reproduced the destructive rollback race and
preparation cancellation issue, then reviewed the fixes.

## Findings and changes

| Finding | Impact | Change |
| --- | --- | --- |
| Cleanup deleted active backups/stages; rollback removed the destination before checking its backup | A second updater could leave neither app nor backup | Persistent per-destination flock, inherited by the helper; cleanup skips active work; rollback validates the backup and preserves recoverable copies on failures |
| Cancellation was only checked after the download | Cancel during mount/copy/verification could still swap and relaunch | Cancellation checkpoints between preparation steps and immediately before swap; temporary cleanup and detach finish before returning |
| Cancelled quit fallback ignored sleep cancellation and only checked dialogs before awaiting the host | Forced exit after cancellation or a sheet appearing during save | Cancellation, pending-install token, and all windows' sheets checked before and after saving |
| An already-cancelled download could leave a suspended task retaining its session/delegate | Leaked downloader/session | Preflight cancellation and invalidate-and-cancel on every exit |
| Numeric version parsing accepted empty components and silently overflowed integers | Invalid releases or mismatched versions could compare incorrectly | ASCII decimal components, string-based comparison, and explicit valid-version equality |
| Release-note links could use arbitrary URL schemes | Clicking a note could invoke a local handler | Only HTTP/HTTPS note links; parsed GitHub page links require HTTPS and the GitHub host |
| Release-note headline came from a filtered final commit | A final WIP/bump could become the published headline | Choose the newest included subject; regression coverage for a trailing WIP commit |

The existing Apple-anchored signature requirement, exact Team ID, bundle identifier, release-version check, and
Gatekeeper assessment remain mandatory. No signature-verification bypass was demonstrated.

## Verification

Verification uses temporary app copies and fixtures. No installed app is swapped or launched by these checks.

- `swift build -Xswiftc -warnings-as-errors`
- `APPUPDATER_LIVE=1 swift test -Xswiftc -warnings-as-errors` — 63 tests passed, no failures or skips; no compiler warnings
- `APPUPDATER_LIVE=1 swift test --filter InstallerTests.testLiveOffloadReleaseVerifies`
- `scripts/test-release-notes.sh`
- `git diff --check`

Build, release-note script checks, and whitespace validation passed. No host deployment was run.

The independent reviewer also compiled isolated fixture probes against the final installer sources and verified helper
lease transfer when the parent's lock occupied descriptor 9 or descriptor 0 (closed stdin). Both retained exclusive
ownership after the parent released its lease. The temporary duplicate used for spawn is always above descriptor 9,
and downstream `open` commands close the helper's lock descriptor.

The live check downloads Offload's public release, mounts its DMG read-only, stages and verifies the app, and rejects a
different bundle ID. Offline tests also verify a scratch copy of the installed Developer ID signed/notarized Offload,
reject unsigned/ad-hoc/wrong-team/wrong-version apps, exercise real AppKit quit hosts, and test helper lock inheritance.

The initial sandboxed baseline could not write user caches or access signature services. The relevant baseline tests
passed with normal macOS access; the full suite requires that access. The original notes fallback test also shared a
cache identifier with unrelated tests; it now uses a unique identifier.

## Remaining boundaries

- Full host rebuilds, physical interaction with their busy/save flows, app packaging, and distribution belong to each
  host repository and were not performed as part of this package audit.
- The relaunch helper detects an `open` failure, not a crash after LaunchServices accepts the launch. There is no startup
  health acknowledgement; the backup is removed two seconds after an accepted launch.
- Cancellation waits for the current system tool to finish so cleanup cannot race its file writes or mount operation.
- No CI/deployment infrastructure was added. Deployment of host apps was not run.
